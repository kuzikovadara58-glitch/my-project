# Электронный журнал тренировок — автоматизация

Desktop-приложение для автоматического заполнения электронного журнала
спортивных тренировок: вход в аккаунт, поиск нужного занятия, прикрепление
фотографии, отметка посещаемости и указание причин отсутствия.

Приложение рассчитано на тренера или администратора без навыков
программирования: утром он открывает приложение, видит тренировки на
сегодня и нажимает «Запустить автоматизацию». Для работы не требуются
Python, VS Code, терминал или редактирование файлов настроек.

> **Статус:** проект в разработке, этап 3 из 8 («Desktop GUI + Scheduler +
> безопасный mock-цикл автоматизации»). Окно уже открывается и умеет
> заполнять расписание в фоне — но пока только имитацией (mock), реальный
> сайт журнала ещё не подключён. См. [CURRENT_STATE.md](CURRENT_STATE.md).

## Технологический стек

Python 3.11+ (проверено на 3.14.6), PySide6, Playwright, PyYAML,
python-dotenv, pytest, `keyring`, `platformdirs`, `tzdata`, PyInstaller
(сборка под Windows, будет добавлен на этапе «Сборка»). Точные версии — в
[requirements.txt](requirements.txt), проверены совместной установкой в
чистое окружение и прогоном тестов.

## Важные принципы проекта

- Журнал не заполняется до начала занятия и не заполняется автоматически
  задним числом за пропущенное по времени занятие.
- Никакие причины отсутствия не придумываются и не выбираются случайно.
- Используются только реальные фотографии с самой тренировки; метаданные
  фото не подделываются.
- Есть проверочный (dry-run) режим, который ничего не меняет в журнале.
- Секреты (логин/пароль от журнала) хранятся через системное хранилище
  учётных данных ОС, а не в коде или в репозитории.

Полный список постоянных правил — в [CLAUDE.md](CLAUDE.md).

## Для разработчиков

Этап 3 добавил desktop-окно (PySide6), фоновый планировщик и безопасную
имитацию обработки занятия (mock) — реальный сайт журнала ещё не
подключён, это отдельные будущие этапы (см. [docs/PLAN.md](docs/PLAN.md)).

### Установка

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### Запуск приложения

Обычный режим — использует реальные `config/` и историю пользователя:

```
python main.py
```

Демонстрационный режим — на временных данных, занятия наступают через
несколько секунд, а не по реальному расписанию (config/ и реальная история
не затрагиваются):

```
python main.py --demo
```

Проверка сценария с ошибкой обработки (только вместе с `--demo`):

```
python main.py --demo --simulate-error
```

В окне: сегодняшние тренировки со статусами, кнопки «Запустить
автоматизацию» / «Остановить», «Последнее событие» и просмотр ключевых
настроек. Ни в одном из режимов реальный электронный журнал не изменяется —
обработку выполняет `MockJournalAutomation`
(`journal_automation/automation/mock.py`).

### Тесты

```
pytest
```

### Демонстрационный сценарий (без GUI, в консоли)

Показывает тренировки на сегодня из `config/` (вымышленные данные), их
состояния и посещаемость — без обращения к какому-либо сайту:

```
python scripts/demo_today.py
```

### Переменные окружения для разработки

- `JOURNAL_CONFIG_DIR` — где искать `settings.yaml`/`groups.yaml`/
  `absences.yaml`/`absence_reasons.yaml` (по умолчанию — `config/` в этом
  репозитории). Укажите отдельный приватный каталог, если работаете с
  реальными (не примерными) данными — так они не попадут в этот репозиторий.
- `JOURNAL_APP_DATA_DIR` — где хранить историю выполнения и другие локальные
  данные (по умолчанию — системный каталог данных пользователя, см.
  `journal_automation/paths.py`).
- `.env` (см. `.env.example`) — секреты только для локальной разработки,
  требует `JOURNAL_ALLOW_DOTENV_SECRETS=1`. В остальных случаях логин/пароль
  от журнала хранятся через `journal_automation.secrets.save_journal_credentials`
  (системное хранилище учётных данных ОС).
