# Электронный журнал тренировок — автоматизация

Desktop-приложение для автоматического заполнения электронного журнала
спортивных тренировок: вход в аккаунт, поиск нужного занятия, прикрепление
фотографии, отметка посещаемости и указание причин отсутствия.

Приложение рассчитано на тренера или администратора без навыков
программирования: утром он открывает приложение, видит тренировки на
сегодня и нажимает «Запустить автоматизацию». Для работы не требуются
Python, VS Code, терминал или редактирование файлов настроек.

> **Статус:** проект в разработке, этап 4 («Google Drive Photo Source»).
> Окно открывается, умеет заполнять расписание в фоне и получать фото
> тренировки из Google Drive — но обработка занятия в журнале пока
> имитация (mock), реальный сайт журнала ещё не подключён. См.
> [CURRENT_STATE.md](CURRENT_STATE.md).

## Технологический стек

Python 3.11+ (проверено на 3.14.6), PySide6, Playwright, PyYAML,
python-dotenv, pytest, `keyring`, `platformdirs`, `tzdata`, Pillow (чтение
EXIF), `google-api-python-client`/`google-auth-oauthlib` (Google Drive),
PyInstaller (сборка под Windows, будет добавлен на этапе «Сборка»). Точные
версии — в [requirements.txt](requirements.txt), проверены совместной
установкой в чистое окружение и прогоном тестов.

## Важные принципы проекта

- Журнал не заполняется до начала занятия и не заполняется автоматически
  задним числом за пропущенное по времени занятие.
- Никакие причины отсутствия не придумываются и не выбираются случайно.
- Используются только реальные фотографии с самой тренировки; метаданные
  фото не подделываются.
- Есть проверочный (dry-run) режим, который ничего не меняет в журнале.
- Секреты (логин/пароль от журнала) хранятся через системное хранилище
  учётных данных ОС, а не в коде или в репозитории.

Полный список постоянных правил — в [CLAUDE.md](CLAUDE.md).

## Для разработчиков

Этап 4 добавил получение фотографии тренировки из Google Drive
(`journal_automation/photos/`) поверх desktop-окна и планировщика из этапа
3. Реальный сайт журнала по-прежнему не подключён — обработку занятия
имитирует `MockJournalAutomation`, теперь уже получая на вход выбранное
фото (см. [docs/PLAN.md](docs/PLAN.md)).

### Установка

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### Запуск приложения

Обычный режим — использует реальные `config/` и историю пользователя:

```
python main.py
```

Демонстрационный режим — на временных данных, занятия наступают через
несколько секунд, а не по реальному расписанию (config/ и реальная история
не затрагиваются):

```
python main.py --demo
```

Проверка сценария с ошибкой обработки занятия (только вместе с `--demo`):

```
python main.py --demo --simulate-error
```

Проверка сценариев поиска фото (только вместе с `--demo`, взаимоисключающие
между собой и с реальным Google Drive — не обращаются к нему):

```
python main.py --demo --simulate-photo-missing     # фото не появляется в Drive
python main.py --demo --simulate-drive-error       # Google Drive недоступен
python main.py --demo --simulate-photo-ambiguous   # несколько подходящих фото
```

В окне: сегодняшние тренировки со статусами, статус «Фото: ...» и кнопка
«🔄 Проверить фото» на каждое занятие, кнопки «Запустить автоматизацию» /
«Остановить», «Последнее событие» и просмотр ключевых настроек. Ни в одном
из режимов реальный электронный журнал не изменяется — обработку выполняет
`MockJournalAutomation` (`journal_automation/automation/mock.py`), получая
на вход уже выбранное и скачанное фото (или `None`, если источник фото не
настроен).

### Тесты

```
pytest
```

Один тест (реальная проверка Google Drive API) помечен `google_drive` и не
входит в обычный прогон (`pytest.ini`: `addopts = -m "not google_drive"`).
Запускается только вручную, когда настроены реальные Google-credentials и
тестовая папка:

```
pytest -m google_drive
```

### Демонстрационный сценарий (без GUI, в консоли)

Показывает тренировки на сегодня из `config/` (вымышленные данные), их
состояния и посещаемость — без обращения к какому-либо сайту:

```
python scripts/demo_today.py
```

### Переменные окружения для разработки

- `JOURNAL_CONFIG_DIR` — где искать `settings.yaml`/`groups.yaml`/
  `absences.yaml`/`absence_reasons.yaml` (по умолчанию — `config/` в этом
  репозитории). Укажите отдельный приватный каталог, если работаете с
  реальными (не примерными) данными — так они не попадут в этот репозиторий.
- `JOURNAL_APP_DATA_DIR` — где хранить историю выполнения и другие локальные
  данные (по умолчанию — системный каталог данных пользователя, см.
  `journal_automation/paths.py`).
- `.env` (см. `.env.example`) — секреты только для локальной разработки,
  требует `JOURNAL_ALLOW_DOTENV_SECRETS=1`. В остальных случаях логин/пароль
  от журнала хранятся через `journal_automation.secrets.save_journal_credentials`
  (системное хранилище учётных данных ОС).

## Google Drive — фотографии

### 1. Где вставляется ссылка на папку

В `config/settings.yaml` (или в приватном каталоге, на который указывает
`JOURNAL_CONFIG_DIR`), раздел `photos.google_drive.folder_url` — обычная
ссылка на папку Google Drive (например
`https://drive.google.com/drive/folders/<id>`). Пока ссылка не вставлена
(пусто, как сейчас) — источник фото отключён, приложение работает как на
этапе 3, без проверки фото. Вместо ссылки можно указать голый
`photos.google_drive.folder_id`.

### 2. Как проходит авторизация в Google

При первом реальном обращении к настроенной папке приложение откроет
браузер для входа в Google-аккаунт (OAuth 2.0, стандартный вход для
десктопных приложений — пароль от аккаунта приложению не передаётся).
Понадобится:

1. Создать проект в [Google Cloud Console](https://console.cloud.google.com/),
   включить Google Drive API.
2. Создать OAuth client ID типа **Desktop app**, скачать `credentials.json`.
3. Положить его в пользовательский каталог данных приложения под именем
   `google_drive_credentials.json` (путь — `journal_automation/paths.py:
   AppPaths.user_data_root`; узнать точный путь можно, открыв «⚙ Настройки»
   в приложении, либо через `AppPaths.resolve().user_data_root` в Python).
4. После первого успешного входа рядом появится `google_drive_token.json`
   (обновляется автоматически, повторный вход не нужен, пока доступ не
   отозван).

`credentials.json`/`token.json` никогда не коммитятся (см. `.gitignore`).

### 3. Рекомендуемая структура папок

```
Google Drive/
    Trainings/            (или любое имя — не зашито в код)
        kids_1/
            2026-09-28_18-07.jpg
        kids_2/
            2026-09-28_20-04.jpg
```

Подпапка с именем, совпадающим с id группы — необязательна: если её нет,
поиск идёт по всей указанной папке и различает группы по имени файла.

### 4. Рекомендуемый формат имени файла

```
2026-09-28_18-07.jpg              (дата_время)
kids_1_2026-09-28_18-07.jpg       (group_id_дата_время)
```

Другие имена не парсятся (сложный разбор произвольных имён — источник
ошибок), но не отбрасываются автоматически: если у файла есть EXIF, дата
съёмки берётся из него независимо от имени.

### 5. Как определяется дата/время съёмки

Приоритет: **EXIF DateTimeOriginal/DateTimeDigitized** → **дата/время из
имени файла** → метаданные Google Drive (`createdTime`/`modifiedTime`) —
только если явно включено `photos.allow_drive_timestamp_fallback: true`
(по умолчанию `false`, т.к. это ненадёжный источник). Ничего из этого не
подделывается ради совпадения с расписанием.

### 6. Как работает ожидание появления фото

Занятие переходит в статус ожидания (`WAITING_FOR_PHOTO`, в интерфейсе —
«🕐 ожидание») и проверяется повторно каждые
`photos.recheck_interval_seconds` секунд, пока не пройдёт
`photos.wait_for_photo_until_minutes_after_end` минут после конца занятия —
после этого статус становится «требует внимания», а не считается ошибкой
навсегда. Кнопка «🔄 Проверить фото» запускает проверку немедленно, не
дожидаясь автоматического опроса.

### 7. Что происходит, если Google Drive недоступен

Отдельный статус («❌ Google Drive недоступен») — отличается от «фото не
найдено»: нет сети, истёк токен, отозван доступ к папке, неверный
`folder_id` или временная недоступность API после исчерпания повторных
попыток. Занятие помечается как требующее внимания, автоматизация
продолжает работать с остальными занятиями.

### 8. Где хранится временный кэш

Скачанные файлы временно лежат в `<пользовательский каталог данных>/cache/photos/`
(не рядом с программой и не в этом репозитории) и удаляются автоматически
через `photos.cache_retention_days` дней — кроме файла, который сейчас
используется. Сам Google Drive этой очисткой никогда не затрагивается.
